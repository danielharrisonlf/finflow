# FinFlow 0.6.0

Versão **incompatível com a 0.5.0 no assistente** (MINOR antes da 1.0.0, pela política de versões). O resto do
FinFlow — contas, cartões, projeção, planilhas, metas, investimentos, dívidas, espaços — continua igual, e o seu banco
é aberto e migrado sem ação manual.

## Alterações

- O assistente "Pergunte ao FinFlow" usa **só a API do Claude com a sua chave**. Ative em **Configurações →
  Assistente (IA)** (campo da chave, **Salvar**, **Remover chave**) ou com a variável `ANTHROPIC_API_KEY`.
- **Sem chave, o assistente fica desativado e escondido**: some do menu, da barra inferior e da paleta de comandos, e
  a captura de comprovante não aparece. Todo o resto funciona normalmente, inclusive o **Posso comprar?** (Projeção e
  Desejos), que não usa IA.
- `finflow perguntar` avisa que o assistente está desativado quando não há chave e explica como ativar.
- Configurações: a seção **API e IA** passa a se chamar **API e MCP** (**Sistema** no app do navegador).
- Landing e README descrevem o assistente como opcional, com a chave da API do Claude.

## Removido

- Provedores locais do assistente (Ollama e servidores compatíveis com a API da OpenAI, como LM Studio e llama.cpp) e
  a detecção automática de um Ollama local.
- `PUT /api/ai/config`, `GET /api/ai/models` e os campos `provider`, `baseUrl`, `visionModel` e `reachable` de
  `GET /api/ai/status`.
- Variáveis `FINFLOW_AI_PROVIDER`, `FINFLOW_AI_BASE_URL`, `FINFLOW_AI_MODEL`, `FINFLOW_AI_VISION_MODEL`,
  `FINFLOW_AI_API_KEY` e `FINFLOW_OLLAMA_URL`.
- Docker: `docker compose --profile ai` (serviços `ollama` e `ollama-pull`) e o volume `finflow_ollama`.

## Compatibilidade

- **Banco e backups:** bancos e backups `.db`/`.zip` de 0.2.0 a 0.5.0 abrem sem ação manual, no programa instalado e
  no app do navegador.
- **Quem usava um modelo local na 0.5.0:** a configuração salva é ignorada e o assistente fica desativado até você
  colocar uma chave do Claude. Remova as variáveis `FINFLOW_AI_*`/`FINFLOW_OLLAMA_URL` do seu `.env`.
- **Docker:** `docker compose up -d` continua igual (serviço `app`, volume `finflow_data`). Se você usava
  `--profile ai`, rode `docker compose --profile ai down` uma vez para parar o Ollama e, se quiser liberar espaço,
  `docker volume rm <projeto>_finflow_ollama`.
- **Scripts que chamavam `/api/ai/config` ou `/api/ai/models`:** use `PUT /api/ai/key` com `{ "apiKey": "..." }`.

## Instalação

- **Executável:** baixe o pacote do seu sistema abaixo, extraia e abra o `finflow` (Windows: dois cliques no
  `finflow.exe`). Seus dados ficam em `%AppData%\finflow\finflow.db` (Windows), `~/.config/finflow/finflow.db`
  (Linux) ou `~/Library/Application Support/finflow/finflow.db` (macOS).
- **Código-fonte:** `git clone https://github.com/danielharrisonlf/finflow && cd finflow && pnpm install && pnpm start`.
- **Docker:** `docker compose up -d` (com o assistente: `ANTHROPIC_API_KEY=sk-ant-... docker compose up -d`).
- **Sem instalar:** https://finflow-landing-umber.vercel.app/app/ (dados guardados no navegador).

Binários sem assinatura de código: o Windows SmartScreen e o Gatekeeper do macOS avisam na primeira execução.

## Verificação

Compare o SHA-256 do pacote baixado com o `checksums.txt` desta release:

```bash
sha256sum -c checksums.txt --ignore-missing          # Linux
shasum -a 256 -c checksums.txt --ignore-missing      # macOS
```

```powershell
(Get-FileHash .\finflow-windows-amd64.zip -Algorithm SHA256).Hash   # Windows: compare com a linha do checksums.txt
```

Depois, `finflow version` deve responder `finflow v0.6.0`.
